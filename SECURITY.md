# Security

0.1.x is a preview. Security fixes are provided as project capacity permits; no response time or support period is promised.

Do not put private manuscripts, databases, credentials, personal paths or a working exploit in a public issue. If GitHub private vulnerability reporting is enabled, use the repository Security tab to report privately. If unavailable, open a minimal issue requesting a private reporting channel without disclosing the vulnerability. No private contact address is currently advertised.

Through the available private channel, include affected versions, platform, impact and a sanitized reproduction. Non-sensitive bugs belong in Issues. Optional embedding/reranking endpoints receive associated text when enabled by the user. Hooks require user review and trust; installation does not grant it.
