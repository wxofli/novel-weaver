# 从第一章开始

先按 [README](../README.md#安装)安装、重启 Codex，并审阅 hooks。以下对话都在**作品目录**进行。插件目录与作品目录是两回事。

## 新建作品

1. 建立空目录，例如 `books/雾港来信`，在 Codex 中打开它。
2. 说：“在这个目录新建《雾港来信》，背景是潮汐反常的港口。先讨论主角和悬念，不写正文。”Codex 应明确书目录并初始化项目。
3. 选定方案后说：“写第一章，约一千字，保存为候选稿并做连续性审查。”
4. 读稿和审查。修改就说清改动；满意后说：“采用刚刚审查的这一版。”只采用你看过的具体版本。

采用时，正文和对应记忆一起提交。修改后的稿件是新版本，需要重新提取与审查；旧版本的采纳不会转给新稿。等待采纳时暂停属于正常行为。

## 导入示例或旧稿

[原创示例](../examples/雾港来信.txt) 随项目使用 MIT 许可，可以自由修改。

1. 新建另一个空作品目录，在其中打开 Codex。
2. 说：“把这份示例 TXT 导入到这本新书。先预览分章映射，等我确认再开始。”给出示例文件的完整路径。
3. 检查预览是否识别为两章，再说：“确认这个映射，开始导入并把记忆同步完成。”
4. Codex 应顺序读取不可变章节源、提取有引文的记忆，直到同步完成。中断后说：“检查这本书状态，继续未完成的记忆同步。”

导入只允许空书。正文已登记而记忆未完成时，不应声称整本书就绪。

## 查询与续写

问：“第一章结束时，林澈知道信是谁写的吗？请给原文证据。”或：“检查第二章有没有把作者知道的秘密提前给主角。”

续写时说：“根据已有正史写第三章，保持林澈的有限视角，先保存和审查，等我采纳。”查不到证据应明确说不确定；计划与草稿不等于已发生事实。

## 更新与卸载

标签来源固定在一个版本。先备份作品，再下载新版本并阅读更新记录。用 `codex plugin marketplace list --json` 核对来源；已注册的是另一标签时，安装器会停止而不会静默替换。确认只更换本项目来源后，手动移除本插件和来源：

```sh
codex plugin remove novel-weaver@wxofli-novels --json
codex plugin marketplace remove wxofli-novels --json
```

随后运行新版本 `scripts/install.py`，重启 Codex，再审阅 hooks。使用本地源码时先更新源码，再运行同一个 `--local .` 安装命令；若 Codex 保留旧版本，先移除本插件再重装。不要删除不属于本项目的 marketplace。

卸载执行上面两条移除命令即可。作品目录、稿件和 `.novel` 由你保留；安装器没有删除作品的功能。

## 遇到问题

找不到 `codex` 或 `uv`：确认工具已安装并在当前终端 PATH 中，重开终端再试。Windows 安装器优先使用 `codex.cmd`，避免 PowerShell 脚本执行策略拦截。

工具启动失败：重新运行安装器，检查实际 `installedPath` 和依赖安装错误。hooks 无状态提醒：检查客户端支持情况及信任状态，见[技术说明](advanced.md#hooks)。

记忆待同步或投影冲突：让 Codex 检查书状态与待办，保留数据库和手工文件，不直接修改 SQLite。报告问题时使用删去私密正文、路径和密钥的最小复现。
