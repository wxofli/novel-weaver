# 历史 traces 驱动的优化验证

本次优化仅修改插件源码及隔离合成测试，随后按作者要求准备 0.1.6 发布。发布不安装插件，未修改真实作品的正文、数据库、记忆、AGENTS.md 或父线程状态。作者原文不进入仓库。

## 样本与口径

只读分析一个 75 章作品的 16 份历史会话文件，截止 UTC `2026-11-16T02:30:30.633Z`。按调用 ID 去重，排除继承的其他线程事件；无法解码的旧 MCP 返回保留为未知，不按成功统计。`awaiting_author` 是流程状态，不是失败。

6,167 次 MCP 调用中，5,834 次为 ok/awaiting_author，170 次明确失败（含 13 次 schema 错误），163 次结果未知；已知结果成功率为 97.17%。这不是文学准确率。错误中有 112 次 ENTITY_NOT_FOUND、26 次 BUDGET_EXCEEDED。脚本不推断这些错误全部可以消除。

成功 source_get 共 2,340 次，其中同线程、同书、同版本、同分页键重复 867 次，重复正文累计 2,946,411 字符。这是缓存机会的上限；独立审查、缺页、上下文丢失时仍需读取。5,991 次返回同时包含相同的 text/structuredContent，为保持客户端兼容，本次没有删除其中一种，也不将其直接换算成计费 token。

## 按历史修订顺序运行真实接口

从日志提取 16 次修订次序：58、61、64、65、63、68、69、70、73、74、75、51、21、23、4、1。以合成的 75 章书稿分别执行原逐章采纳/同步流程和新批量流程。每一章的内容、事实和证据均为合成材料；不是把旧错误请求重发给真实书库。

| 指标 | 原逐章流程 | 新批量流程 |
|---|---:|---:|
| 语义提取章次 | 376 | 75 |
| 本地工具调用 | 1,176 | 141 |
| source_get 次数 | 376 | 16 |
| 单次本地运行耗时 | 23.215 秒 | 6.389 秒 |

提取章次下降 **80.05%**，该固定流程调用次数下降 **88.01%**。两条路径最终已采纳正文哈希、事实 ID/主体/谓词/值一致，frontier 均为 75，活动任务均已结束。短篇测试亦覆盖此对照并自动断言结果一致。

限制：批量方案假定这些修订可以在同一基线与授权范围内一起准备；不同作者决定不能强行合批。旧流程基准使用 next/get/apply，尚未采用新增的内联下一源能力；调用收益同时包含合批和减少往返。合成章很短，未测模型推理、真实长篇阅读质量或实际 token 费用；单次耗时不是稳定性能承诺。候选验证内部仍重建前缀，数据库 CPU 随规模增长仍有优化空间。

## 正确性与兼容性

测试覆盖：候选阶段正式指针/记忆不变；新前缀实体/事实与后章知情引用；顺序、哈希、原文证据、审查、上下文、revision 和指纹校验；重复操作幂等；跨连接恢复与中止；提交中途故障全部回滚并可重试；手工 Markdown 不被覆盖；实体历史别名、重名、类型、POV 及跨书边界；条件读取与分页；CLI/MCP 共用错误；公开 JSON Schema 的有效/无效请求对照。

候选 context 明确为作者事实视图，不伪装角色知情视图。条件授权和独立审查的执行者认证仍由工作流负责；这次没有把“存在 review”升级为“文学合格”。schema 重点是可发现的条件与统一错误，不声称新增工具后 schema 总体字符更少。

优化完成时完整回归 **146 passed**（76.76 秒，1 条既有 jieba/pkg_resources 弃用提示），包括官方 MCP 客户端与 stdio 验证。10 个 skill 的 quick_validate 均通过；Markdown 引用与包内依赖图测试通过，另生成隔离插件 ZIP 并确认包含新后端、协议、验证说明和分析脚本；git diff --check 通过。0.1.6 发布准备统一版本元数据，未新增依赖；远端发布由标签工作流运行 Windows/Linux 和 Python 3.11–3.13 矩阵验证后生成附件。复现命令（在源码根运行，使用项目虚拟环境）：

```sh
python -m pytest -q --basetemp .cache/optimization-final-tests
python scripts/benchmark_revisions.py
python scripts/analyze_traces.py --session-db /path/to/state_5.sqlite --project /path/to/book --before 2026-11-16T02:30:30.633Z
```

trace 脚本只读 session 索引和日志，输出汇总，不调用书工具、不输出原文。合成 benchmark 只在源码 `.cache` 的临时目录建书并清理自身目录；无真实作品输入参数。持续写入的日志只读取开始时的文件长度，正式收益对照使用固定时间截点。日内章节末端变化的样本不计算可合批收益。
