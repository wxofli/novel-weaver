# 候选快照、schema 与返回内容的第二轮验证

状态：优化完成后按作者要求准备 0.1.7 发布。发布不安装或修改主线程插件，未修改真实小说正文、记忆库、项目配置或 AGENTS.md。历史 traces 只读，原文不进入仓库；事务测试与性能实验使用隔离合成作品。

## 实现与正确性边界

1. MCP 公布 schema 时只删除自动 title 注释，保留 properties.title、default/const/enum 中的字面内容、描述、必填字段、范围、条件及错误结构。SDK 与核心校验模型未精简。
2. 候选快照只包含 entities/facts/knowledge/hooks/summaries 五张图表，独立内存数据库承接下一章增量。派生表 revision_snapshots 按需创建，快照与 batch/游标同事务保存；不会把候选数据换进正式图。按书、任务、基线、游标、manifest、源正文/哈希及增量内容校验缓存绑定。缺失、损坏、格式或绑定变化时重新重放；commit 仍完整验证并重放全部候选，abort/commit 清理快照。没有长期跨工具持有的事务，也不依赖进程内全局缓存恢复。
3. MCP 默认仍返回完整 text JSON 与 structuredContent。只有明确配置 NOVEL_WEAVER_MCP_TEXT_MODE=summary 才去掉 text 副本中的 data；完整正文与证据留在 structuredContent，状态、版本、错误、警告和下一步保留两份。官方 MCP 客户端已验证两个模式；未在当前 Codex 主线程启用或声称所有宿主都兼容。仅消费 text 的客户端必须保留 full。CLI 不变。
4. SourcePageCache 是显式调用方辅助库，不自动拦截工具。按 project/book/source/page 区分，默认 20 万正文字、128 页、5 分钟期限；仅收录实际持有且分页完整的源页。缺页、换版本、上下文丢失或独立读者交接时重新读取。缓存不保存 context_id、授权或书状态。服务器既有 if_none_match 仍须调用方真实持有内容。

## Schema 与历史返回的可重复测量

同一 SDK 的 18 个工具声明，紧凑 JSON 总量由 **55,503 → 44,949 字符，减少 19.02%**。未减少工具数或校验条件。它是目录声明体积，不代表每轮都会进入模型的 schema token 数。

历史样本：16 份会话，固定截点 UTC 2026-11-16T02:30:30.633Z，按调用 ID 去重并排除其他线程的继承事件。可解码 5,991 个结果，176 个结果不可用于此模拟（含旧 schema 错误文本），未强行解析或归为成功。

| 模拟项目 | full | summary |
|---|---:|---:|
| text 通道字符 | 18,178,986 | 1,639,515 |
| 完整 CallToolResult 序列化字符 | 37,656,004 | 20,100,633 |

完整返回字符减少 **46.62%**，完整 structuredContent 保持一致。历史样本未实际启用该模式，此处重算返回结构，不是实际模型 token/费用观测。旧版结构不规范的返回未计入。

在相同日志上模拟调用方缓存，并在观察到的 50 次上下文压缩事件清空：2,340 次成功 source_get 中命中 **239 次（10.21%）**，可避免再次传输正文 **814,297 字符**。它明显小于此前 867 次同键重复的理论上限；模拟仍假定缓存未因其他未知原因丢失。客户端返回缓存全文仍可能进入模型上下文，减少 RPC 不自动等于减少模型输入。

## 候选重放对照

使用同一套真实核心接口，历史的 16 个修订章次序，75 章合成书稿；每次 apply 前均请求候选 context。对照分支以 v0.1.6 的 savepoint 重建方式验证前缀，实验分支使用快照；两者均保留最终重放。

详细运行结果由 scripts/benchmark_revisions.py 输出：工具调用次数、增量应用次数、SQLite 执行次数、快照峰值、耗时及最终图/正文一致性。计数包括 executemany 实际提交的行数；快照恢复不是把每行重新 INSERT。对照比较全部五张图表，来源 ID 规范化为源章号与哈希，不把随机 UUID 差异误判为内容差异。

密集样本每章 20 条事实及对应的角色/读者知情，总计 1,500 条事实、3,000 条知情。下表为没有并行运行测试时的一次本地测量：

| 指标 | 每次重建前缀 | 候选快照 |
|---|---:|---:|
| 工具调用 | 216 | 216 |
| 增量应用次数（含最终重放） | 5,700 | 150 |
| SQLite 执行条数 | 426,969 | 73,753 |
| 本地耗时 | 23.621 秒 | 13.557 秒 |
| 派生快照峰值 | 无 | 757,760 字节（740 KiB） |

增量应用减少 **97.37%**，SQL 减少 **82.73%**，本次耗时减少 **42.61%**。最终五张图表（包含证据坐标、知情与关闭状态）以及正式正文哈希一致，任务结束且 frontier 为 75。快照在提交后删除，不进入正史，也不额外减少这次模型工具调用次数。

小规模或稀疏图的序列化/绑定校验成本可能抵消收益：4 章轻负载初测为 0.891 → 0.973 秒，未获得加速；75 章每章一条事实的初测为 11.877 → 11.339 秒，收益也较小。这些是不同负载的单次观测，不是稳定延迟保证。快照仍需复制、散列、完整性检查和存储，绑定检查随前缀增长，算法并未变成严格线性。不把增量应用次数降幅宣传成总延迟或 token 降幅。

## 验证覆盖

专项测试覆盖缓存命中不重放、损坏/格式变化/缺失后重建、跨书快照拒绝复用、源或增量内容改变后的证据失败、跨进程恢复、保存快照后的中断回滚、重试幂等、commit 不使用缓存替代证据重放、abort 清理、事实关闭与旧信念延续。公开 schema 的条件分支在压缩前后对有效/无效请求保持相同判断；官方 MCP 客户端验证 full/summary 下正文完整、错误标志、partial、警告和下一步。分页缓存测试涵盖身份、版本、页边界、过期、淘汰与清空后重新读取。

## 复现

在源码根使用项目虚拟环境，无需连接真实作品运行事务测试或快照 benchmark：

```sh
python -m pytest -q --basetemp .cache/snapshot-final-tests
python scripts/benchmark_revisions.py --compare-snapshots --include-context --facts-per-chapter 20
python scripts/benchmark_transport.py --session-db /path/to/state_5.sqlite --project /path/to/book --before 2026-11-16T02:30:30.633Z
```

最后一条只读会话索引和日志，输出计数不输出原文；日志不是必要的测试依赖。优化完成时完整回归 **168 passed**（110.13 秒，1 条既有 jieba/pkg_resources 弃用提示）。10 个 skill 的 quick_validate、Markdown 引用/包内依赖测试及 git diff --check 均通过，隔离插件 ZIP 已确认包含新后端、缓存辅助库、benchmark 和报告。0.1.7 发布统一版本元数据，未新增依赖或安装插件；远端标签工作流通过 Windows/Linux、Python 3.11–3.13 矩阵后生成发布附件。
