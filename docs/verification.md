# 验收记录

验收环境：Windows、Python 3.13.11、SQLite 3.51、uv 0.11.29。依赖来自项目的 `uv.lock`，使用独立虚拟环境，未安装到用户全局环境。

## 自动验证

完整测试 **105 passed**（45.29 秒，1 条既有依赖弃用提示），覆盖：

- 同书身份验证、跨书隔离、不可变源版本和事务提交。
- 原文引文与偏移校验、过期上下文票据、候选记忆与审查绑定。
- 先写稿和审查、等待作者、采纳后正文与记忆一起提交。
- 历史状态与别名、作者事实、读者及角色知情；旧信念不会随世界状态变化自动消失。
- 旧章及全局设定修订后的重放、冻结提交、导入和断点恢复。
- 幂等和并发提交、投影文件被占用、损坏或缺失时的保护与恢复。
- 中文分词、FTS、上下文预算；可选嵌入、重排、profile 变化与服务失败降级。
- CLI 参数和 JSON、MCP 有类型的输入输出、官方 SDK 客户端及真实 stdio 通信。
- Hooks 的只读行为、同轮 Stop 边界、计划模式及启动失败处理。
- 安装器的实际安装路径、重复安装、只读预演、配置冲突与失败停止；发布包版本一致性、敏感文件排除及校验和。

```powershell
uv run --locked --extra dev --extra vector pytest -q --basetemp .cache/verification
```

存在一条 jieba 对 `pkg_resources` 的弃用提示；锁文件固定其兼容的 setuptools 版本。未使用真实付费嵌入或重排服务；服务契约和异常路径使用可控响应验证。CI 已配置 Windows/Linux 与 Python 3.11–3.13 矩阵，本地验收只代表上述 Windows 环境。

8 个 Skills 通过结构校验，清单 JSON 和文档请求示例通过检查。独立 Agent 按 Skills 完成了一次新书首章流程：构建上下文、写稿、提取记忆、审查、等待作者；收到“采纳”后提交并查询了正式记忆，未额外询问是否更新记忆。

## 检索基准

```powershell
uv run --locked --extra vector python scripts/benchmark.py
```

合成语料为 **1000 章、200 万字符、5 万事实**，每种操作预热后查询 40 次：

| 操作 | 中位数 | P95 |
| --- | ---: | ---: |
| `search` | 50.84 ms | 92.29 ms |
| `graph_query` | 6.28 ms | 7.95 ms |

两项均返回非空结果。语料直接装载以隔离检索测量，不包含模型、网络、写作或事务导入耗时；该结果只代表本机合成基准，不是实际长篇质量或通用性能保证。原始报告位于本地 `.cache/benchmarks/latest.json`，不包含在发布包中。

## 发布包验证

`scripts/package.py` 以白名单生成 `dist/novel-weaver-0.1.0.zip`，排除虚拟环境、缓存和作者书目录。已在新的目录解压，使用锁文件重新准备依赖，并在解压出的插件上验证：

1. CLI 在中文目录创建书项目、读取状态、构建首章上下文。
2. 标准库 hook 包装器启动实际处理器，返回合法的 SessionStart 状态卡。
3. 插件包含所需清单、8 个 Skills、共享核心、适配器和启动脚本。

## v0.1.0 宿主验证

发布准备阶段还在隔离的 `CODEX_HOME` 中使用 Codex CLI 0.167.1，从白名单 ZIP 的解压目录运行统一安装器。首次安装和重复安装均成功，依赖准备与运行检查使用 Codex 返回的实际插件缓存目录；这验证了本地 marketplace 注册和安装器幂等路径，没有改动用户真实配置或授予 hook 信任。

从实际插件缓存目录启动 MCP stdio，验证了 16 个工具的发现，以及新书初始化和状态读取。

v0.1.0 在实际桌面端安装后，Skills 和 MCP 可用，设置中的 Hooks 列表为空。同一台 Windows 机器上的 Codex CLI 0.167.1 也未加载根 `plugin.json` 声明的 hooks。

## v0.1.1 桌面兼容性

改用 Codex 兼容清单后，实际用户配置下的 Codex 宿主发现了 8 个 Skills、16 个 MCP 工具和 7 个待审阅的 hooks。使用测试小说验证了建书、候选稿采纳后查询图谱事实，以及两章 TXT 导入和记忆同步。

用户在桌面端审阅信任后，宿主报告 7 个 hooks 均已信任。在一轮真实模型会话中，SessionStart 和 UserPromptSubmit 生成了小说状态提醒，PreToolUse、PostToolUse 和 Stop 完成执行。上下文工具通过宿主审批后成功运行，图谱工具返回了第一章的事实和原文。PreCompact 和 Interrupt 在该轮中仅验证了发现和信任状态。

## v0.1.2 场景上下文与 hooks

Windows 本地全量测试通过 110 项，有一条既有依赖弃用提示。新增用例覆盖有限视角的知情边界、审稿取证、长风格素材下的预算裁剪，以及轻量状态读取和 `Stop` 的续跑条件。

从候选 ZIP 解压安装到隔离的 Codex CLI 0.167.1，宿主发现 8 个 Skills、16 个 MCP 工具和 3 个待审阅的默认 hooks。通过宿主调用 MCP，验证了限视角写稿、审稿查看原文、候选稿采纳后的图谱更新，以及两章 TXT 导入和记忆同步。

在样例作品中单独运行包内 hook 启动器，验证了开场和每轮提示各自提供的状态、同轮稿件仅补跑一次记忆提取或审查，以及作者待采纳时停止。此轮宿主验收覆盖工具和数据行为，正文的文学质量留待真实创作评估。
