# 设定与大纲

按作者请求的尺度工作：一个场景只规划该场景，一章只规划该章。保留明确的作者约束；对尚未选择的方案标注候选，不借规划改写作者的主题或人物动机。

已有作品先按[公共协议](../novel/references/workflow.md#调用与身份)读取状态，再用 `context_build(task="plan", chapter=相关章, query=规划目标)` 获取约束，补充 `search(scope="plan")` 和相关 `graph_query`。明确区分角色知道的内容、读者已知信息和作者掌握的秘密。未来大纲不能变成提前发生的事实；上下文超预算时缩小实体或查询，而不是漏掉关键限制。

交付可执行的节奏与因果：每个相关场景说明目标、阻碍、选择及结果，人物转变由事件推动。只在有帮助时提供多个方向，不强制固定章数、爽点频率或模板。

作者要求持久化时，根据用途保存：

- `outline`：全书、分卷、分章计划；属于 `plan`，不能建立正史图事实。
- `style`：作者指定的叙述与语言要求；作为创作约束。
- `setting`：已明确的世界规则、人物基础设定。
- `decision`：作者作出的具体创作决定，保留原话与适用范围。

用 `source_save` 生成不可变新版本；替换已读材料时带上 `expected_source_hash`。只有作者已明确采用的设定/决定才提取并暂存有证据的完整源声明快照，再 `source_accept` 提交。该快照须在同一 `entities` 声明全部引用实体，知情只能引用同一 delta 的事实，禁止 `close_facts`；撤回旧断言须替换原 `logical_id` 的完整源。采用计划或风格作为后续参考时可直接采纳该材料，不为它创建剧情事实。完整规则与采纳参数见[公共协议](../novel/references/workflow.md#证据与记忆增量)。只要求讨论或评估方案时保持对话，不保存或采纳。

接受设定/决定后检查响应 `job_id` 和 `book_status.active_job`；替换可能撤回旧源并触发全部已采纳章节重放，有活动任务立即交 [novel-memory](../novel-memory/SKILL.md) 完成，不再询问已采纳正文的记忆授权。接到正文任务转 [novel-write](../novel-write/SKILL.md)。对已经发生的剧情做修改也会引发重放，不能只改大纲或 Markdown 后声称正史已更新。
