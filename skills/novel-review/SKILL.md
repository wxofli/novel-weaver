# 正文审查

先明确具体 `source_version`、范围与审查目标。本轮已完整读取且 ID、哈希一致时，复用原文；否则通过 `source_get` 翻页读到 `next_offset=null`。工具格式见[公共协议](../novel/references/workflow.md#调用与身份)。作者只粘贴一段文字要求建议时，直接审查该段。章段、全书及多个候选结局按[审查模式](../novel/references/review-modes.md)工作；长材料按[分批阅读](../novel/references/reading.md)维护覆盖与期待台账，未读关键范围不能先作全书通过判定。

在当前项目用 `context_build(task="review", chapter=N, draft_id=仅限被审的精确版本, query=审查目标)`，按需用 `search`、`graph_query(chapter=相应历史边界,pov=相关角色稳定ID或reader)` 核实。图查询和上下文的 POV 不解析名字/别名；不带 POV 的历史名字查询也只按当章已引入字典解析。审前文时不能把后续已发生信息当成当时人物已经知道的事；人物旧信念在知情更新或 `rejects` 前可能与作者事实不同，不直接判作连续性错误。未采纳候选仅作该稿工作覆盖层。

先检查作者指定的层面。综合审查先按读者顺序通读，标出吸引、困惑、跳读与情绪落空的位置，再查场景目的、因果、动机、信息揭晓和人物声音。用作者层证据核对原文和人物知情，把确定冲突、需要作者判断的问题和审美建议分开；事实无误不等于阅读有效。

至少指出本章/段的阅读价值、与前文相比的新增变化及应保留的写法。跨章问题同时给建立与回应/冲突位置。重要发现说明读者影响、最小修法、联动章节和成本；不凑问题、不把固定爽点或强悬念当通用门槛。重复、合理省略、人物误判与开放结局的边界见[正反例](../novel/references/craft-examples.md)。

正文闭环审查须核对叙述人称，以第三人称为默认约定。引用未经作者明确指定的第一人称叙述或突兀切换人称的原句，说明它如何打断场景的视角。按语境识别人物对白、明确标出的直接内心独白和故事中的书信，允许其中保留第一人称。

每条 finding 使用 `severity="info"|"warning"|"critical"`、具体 `message` 和必要的原文 `quote`。引文逐字取自目标源；拿不准就说明证据不足。结构化 `Review` 必须含该章精确的 `source_version` 和 `source_hash`。在项目内需要保存审查或为正文闭环审查时，调用 `source_save(kind="review", logical_id=稳定审查ID, content=可读报告, review=该对象)`，保留返回的 `review_id`。

告诉作者最值得处理的问题及其影响，区分自审与另一执行者实际完成的独立审查。记录已保存不表示审查通过。审查本身不授权修改或采纳；作者要求修订时走 [novel-write](../novel-write/SKILL.md)，并为新稿重新提取和审查。作者已明确采纳当前稿，或已给出且满足适用的条件授权时，按该 Skill 的精确版本流程提交，不再询问记忆授权。
